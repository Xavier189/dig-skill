# Sensemaking（探骊）

> 从你的表达出发，结合真实上下文，挖掘目标、关联影响、知识缺口与设计取舍。

你可以只带来一句需求、一个症状或一个想法。也可以带来写得很完整的功能描述：**表达清楚，不代表实际前提和影响已经核验。**

Sensemaking 帮 Agent 主动查看相关代码、设计或现实材料，发现你尚未提及的关系；能查的自己查，需要解释的先解释，需要你取舍的再讨论，逐步形成适合当前目标的设计。

## 可以直接这样开始

| 你的输入 | 应得到的帮助 |
|---|---|
| “给这个功能加个开关，默认关闭。” | 核对已有开关、默认行为和受影响路径，发现能复用什么、关闭究竟意味着什么 |
| “报表增加几个字段，规则已经写好了。” | 追到数据来源、事件关联、缺失含义与输出时机，形成必要的实现思路 |
| “把直接下发改成主动拉取。” | 检查受理、排队、执行与完成的语义，以及容量、重试和上下游影响 |
| “这个操作偶尔重复执行，帮我解决。” | 结合证据区分原因，检验修复会改变的行为，而不是先让你补全技术分析 |
| “我想把周会改成文字更新。” | 查看现有会议承担的功能，讨论状态同步、决策与阻塞处理的差别 |
| “我想做点长期有价值的东西，还没方向。” | 用具体例子帮助你形成判断依据，不假设心里已经藏着完整答案 |
| “这轮讨论交给另一个 session 继续。” | 保留目标、已定选择、被推翻的假设、未决项和授权边界 |

无需先选择模式或说出遗漏是什么。手动调用时，Codex 可以用 `$sensemaking`，Claude Code 可以用 `/sensemaking`，然后直接描述事情。

## 它怎样工作

![Sensemaking 探索与设计循环：理解目标、核对现实、追踪影响、补足知识、讨论设计，并按新证据继续](docs/assets/sensemaking-routing.svg)

**理解目标 → 核对现实 → 追踪影响 → 补足知识 → 讨论设计 → 按新证据继续或收敛。**

这不是固定问卷，也不是一串批准环节：

- 用户已经说清的目标和约束直接继承。
- 从相关实现或材料出发，沿实际关系发现影响；取得有用证据就回到对话。
- 用户缺少判断基础时，先解释机制和具体后果；局部可逆的实现选择由 Agent 承担。
- 用户回答后，重新检查受影响的建议和后续问题。没有值得问的问题时，可以零提问。
- 设计是探索的一部分，可以形成适度的设计思路，不必先产出 PRD 才继续。

Discover、Clarify、Challenge 是 Agent 按需使用的方法，不是用户必须理解的入口分类。

## 何时直接处理

机械修改、狭窄事实查询，以及相关前提与影响已经核验的执行任务，可以直接处理。例如只改标题、查询某个函数的现有行为，或实施已经讨论验证过的设计。

短小、详细、带源码位置，都不能单独证明任务已就绪。反过来，新消息和新 session 也不代表必须重问已确认的决定。

## 深入分析，守住范围

每个建议都应说明：它影响哪项目标、不处理会怎样、最低需要做到什么程度。

区分完成当前目标的必要工作、相关代价与风险、独立优化机会。发现遗留弱点，不自动把它升级成本次需求；不因增加几个字段而顺带设计整套可靠性平台。

讨论只授权相关调查与分析。回答一个问题只确认对应选择；“继续”继承当前活动。已授权的执行在关键问题解决后继续，不额外重复批准。

## 完成与延续

当关键前提和影响已有依据，重要选择已确认、可见地委托、暂缓或转成具体验证步骤，就完成当前思考工作。无需穷尽所有可能性。

默认在对话中保留理解与决定。用户需要时才生成 PRD、设计文档、ADR、计划或交接记录。跨 session 恢复时继承决定，只刷新缺失或可能变化的事实。专项设计、实现与专业审查按任务需要组合，没有固定后继流程。

## 安装与触发

```bash
git clone https://github.com/Xavier189/dig-skill.git
cd dig-skill
mkdir -p ~/.agents/skills ~/.claude/skills
ln -s "$(pwd)/skills/sensemaking" ~/.agents/skills/sensemaking
ln -s "$(pwd)/skills/sensemaking" ~/.claude/skills/sensemaking
```

目录复制也可使用；软链接会让源文件修改直接影响后续读取。更新后用新 session 检查发现与调用。

隐式调用依赖宿主规则和 Skill 描述匹配，不能仅凭安装成功宣称触发可靠。希望默认对新功能与行为变更开展探索时，在现有全局规则的规范源中加入或合并以下原则，不要重复维护互相矛盾的规则：

> 新功能、行为改造或需要形成解决方案的问题，使用 sensemaking 结合真实上下文核验隐含前提、关联影响与知识缺口，并组织必要的调查、解释、讨论和设计。描述清楚不代表核验完成；机械修改、狭窄事实查询及已完成相关核验的执行任务直接处理。保留既有决定与授权，分析发现不自动扩大实现范围。

安装第三方工作流、增加 hook 或自动写文档都不是使用本 Skill 的前提。
