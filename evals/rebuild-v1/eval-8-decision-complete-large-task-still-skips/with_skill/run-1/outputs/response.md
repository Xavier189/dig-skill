# PostgreSQL 迁移执行清单

## 1. 迁移前准备

- [ ] 确认源库和新库均使用 PostgreSQL，不引入数据库类型变更。
- [ ] 锁定本次迁移范围、表清单、数据总量和迁移顺序。
- [ ] 完成新库 schema、index、constraint、sequence 和权限初始化，并与源库逐项核对。
- [ ] 对源库执行可恢复备份，并完成备份可用性检查。
- [ ] 部署双写逻辑和开关；记录双写开始时间 `T0`，连续运行满 7 天。
- [ ] 配置迁移 checkpoint，确保中断后可从最后一个成功批次继续，已成功数据不会重复写入。
- [ ] 配置自动停止规则：每批按 `失败行数 / 本批尝试行数` 计算错误率，错误率 **> 0.1%** 时立即停止后续批次并告警。
- [ ] 确认负责人、审批人、值守人员和回滚操作人已进入本次变更记录，无需重新指定。

## 2. 双写与存量数据迁移

- [ ] 开启双写，写请求同时落入源库和新库；源库在切读前继续作为读流量来源。
- [ ] 持续监控双写成功率、写入延迟和两库数据差异。
- [ ] 按稳定且不可变的主键顺序迁移存量数据，**每批固定 5000 行**；最后不足 5000 行的尾批按实际剩余行数执行。
- [ ] 每批完成后依次执行：提交事务 → 记录 checkpoint → 核对行数和关键字段 → 计算错误率。
- [ ] 任一批次错误率 **> 0.1%** 时，由自动化立即停止迁移，不再启动下一批；保留现场、批次号、失败记录和日志，由负责人处理后再恢复。
- [ ] 双写期间每日执行增量对账，至少核对总行数、主键集合、关键业务字段和抽样 checksum。
- [ ] 双写连续运行满 7 天，且存量迁移完成、增量追平、对账通过后，才允许进入切读步骤。

## 3. 变更窗口执行（周日 02:00–04:00）

- [ ] 01:45 前完成值守签到、监控面板检查和审批记录确认。
- [ ] 02:00 进入变更窗口，冻结非必要发布和会影响数据一致性的运维操作。
- [ ] 确认迁移任务无运行中批次，源库与新库增量已追平。
- [ ] 执行最终对账；仅在错误率未超过 0.1%、核心表数据一致且新库健康检查通过时继续。
- [ ] 按既定流量切换步骤，将读流量切到新库；双写保持开启。
- [ ] 验证核心查询、分页、排序、聚合、事务读和业务关键路径。
- [ ] 持续观察新库连接数、query latency、error rate、CPU、memory、disk I/O、锁等待和 replication 状态。
- [ ] 04:00 前完成验收；未完成或验收不通过时立即执行回滚。

## 4. 回滚清单

- [ ] 回滚时只把读流量切回源库，不修改既定写入链路。
- [ ] 不删除、不清空、不重建新库数据，保留新库现场供排查和后续续迁。
- [ ] 验证源库读流量恢复、核心业务正常、错误率回落。
- [ ] 记录触发原因、切回时间、受影响范围和后续处理项，由负责人提交审批人确认。

## 5. 完成标准

- [ ] 双写已连续稳定运行 7 天。
- [ ] 所有存量数据均按每批 5000 行迁移完成，checkpoint 完整可追溯。
- [ ] 迁移过程中不存在未处理的 **> 0.1%** 错误率事件。
- [ ] 两库最终对账通过，无未解释的数据差异。
- [ ] 读流量已在周日 02:00–04:00 窗口内完成切换并通过业务验证。
- [ ] 监控、操作日志、审批记录和回滚记录已归档。
