结论：这个设计存在一个 `blocking` 缺陷——它把“主动暴露协作问题”设计成了“公开自我归责后接受领导裁决”。两者的激励方向相反。按当前方案执行，参与者更合理的行为是少说、晚说、只说安全的小错，而不是更早暴露真正棘手的跨人、跨团队问题。置信度：高。

## Dig Challenge Report

### 1. `blocking`：暴露问题的个人风险高于沉默风险

- **Finding**：公开说明“自己哪里做错了”，随后由领导决定整改，实质上把复盘与个人问责绑定。
- **Basis**：这是由会议规则本身可推出的激励结果：发言会留下负面归因并影响领导判断，沉默或淡化问题反而更安全。
- **Consequence**：成员会筛选“可承认、可解释、影响小”的错误；真正涉及领导决策、同事冲突、职责边界和资源不足的问题更难被提出。会议可能增加认错表述，却减少有效信息。
- **Recommendation**：把发言问题从“我哪里做错了”改为“发生了什么协作事件、造成什么影响、为什么没能更早暴露、需要改变哪个接口或机制”。个体失职或纪律问题另设问责流程，不在学习型复盘中现场裁决。

### 2. `material`：领导先讲 40 分钟，会预先定义“正确答案”

- **Finding**：在任何成员发言前，最高权力者先长时间总结问题，会形成强锚定。
- **Basis**：后续每个人只能在领导已经公开定性的框架中发言；提出不同问题等同于公开挑战领导判断。这一判断是基于会议顺序和权力关系的明确推论，置信度：高。
- **Consequence**：会议更容易收集对领导观点的补充和确认，难以发现领导没看到、看错或本身参与造成的问题。
- **Recommendation**：成员必须在领导总结前独立提交问题，至少先静默书写再汇总。领导开场控制在 5–10 分钟，只说明目标、边界和自己在本周期的一项判断失误，不先给完整问题清单。

### 3. `material`：按人认错会把协作问题错误地切成个人问题

- **Finding**：会议单位是“人”，目标单位却是“协作关系与机制”，分析对象不一致。
- **Basis**：协作问题通常发生在交接、信息流、优先级冲突、权限或责任边界上；让每个人只解释自己的错误，会把同一事件拆成互相防御的个人陈述。
- **Consequence**：整改项容易变成“加强意识、提高主动性”这类个人要求，真正的接口、流程和决策机制保持不变，问题会重复出现。
- **Recommendation**：按“事件/协作链路”而不是按人讨论。每个事件固定回答：事实时间线、受影响方、失效的交接点、阻碍提前暴露的条件、最小系统改动。

### 4. `material`：领导单方面决定整改项，会削弱信息质量和执行承诺

- **Finding**：领导既定义问题，又听取认错，最后独自裁决整改，缺少对事实、方案和副作用的共同校验。
- **Basis**：清晰的最终决策权本身是优点，但当前设计没有区分“提供现场信息”“形成候选整改”“处理资源冲突”三种权力。
- **Consequence**：成员会把发言当成向上答辩；整改项可能符合领导视角，却忽略实际执行约束。责任人也容易把行动理解为被指派，而非共同承诺。
- **Recommendation**：由相关成员共同提出候选整改及副作用，领导只对资源、优先级和无法达成一致的冲突作最终决定，并公开说明取舍理由。

### 5. `material`：缺少防御行为约束和验证闭环

- **Finding**：设计只规定了发言顺序，没有规定能否打断、辩解、追责、如何记录，也没有定义整改是否有效。
- **Basis**：一旦敏感问题被提出，现场反驳或会后追责一次，就足以改变下一次会议的发言策略；只有整改项而没有 owner、期限和验证指标，也无法判断复盘是否产生效果。
- **Consequence**：最初几次会议中的负面反馈会迅速固化为沉默规范；同时，团队可能用“提出了多少问题”制造表面进展。
- **Recommendation**：设置中立 facilitator；事实收集阶段禁止打断、辩护和现场定责；整改项必须包含 owner、期限和验证方式。不要用问题数量衡量成功，改看“问题从出现到被暴露的时间”“重复发生率”“跨团队阻塞解除率”，并配合简短的匿名安全感脉冲调查。

## 保留项

这个方案有两点值得保留：固定复盘节奏，以及最终必须形成明确行动。领导保留资源和优先级冲突的最终决策权也合理；需要删除的是“领导先定性—个人公开认错—领导裁决”这条链路，而不是删除领导责任。

## 最小可行改版

1. **会前**：所有人先独立提交协作事件，格式为“事实—影响—为何未提前暴露—希望改变什么”；提交必须发生在领导总结前。
2. **0–10 分钟**：领导说明会议是学习型复盘，公开自己的一项判断失误，并明确复盘内容不直接用于现场个人问责。
3. **10–40 分钟**：facilitator 按事件聚类，选择影响最大的 2–3 个事件还原协作链路；允许成员指出领导和流程问题，不按人轮流认错。
4. **40–55 分钟**：相关人员共同提出整改，每项写清 owner、期限、验证指标和副作用。
5. **55–60 分钟**：领导只裁决未达成一致的优先级或资源问题；2–4 周后检查结果及问题是否更早暴露。

唯一必须由你作出的 **owner decision** 是：是否愿意把个体问责与学习型复盘拆开。若拆开，上述设计与“主动暴露协作问题”的目标一致；若不拆开，就应把会议目标诚实地改成“责任认定与整改”，不能同时期待成员更主动暴露高风险问题。
