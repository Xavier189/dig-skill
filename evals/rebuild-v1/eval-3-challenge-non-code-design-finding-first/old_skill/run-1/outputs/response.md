先结论：按 dig，我现在不会直接给出最终审核结论；先把审核目标和权力边界校准。当前工作假设是：这个议程与“让大家主动暴露协作问题”的目标存在结构性冲突，但冲突是否可修复，取决于问责、领导被复盘的范围和会议性质。

### 工作假设

**你真正想要的**

你要的不是让每个人完成一次“认错”，而是让团队以后更早、更具体、低防御地暴露跨角色、流程和决策中的协作问题，并让这些问题得到整改。

**最容易出错的地方**

- 领导先用 40 分钟定调，再让成员逐一说明“自己哪里做错了”，容易把复盘塑造成归责与服从场；成员会学习如何安全地认错，而不是主动暴露真实问题。
- 整改项完全由领导决定，会让信息解释权和决策权集中在同一人手里，尤其容易压掉涉及领导决策、部门机制或跨层级协作的问题。

**如果被迫现在开始，我会……**

- ✅ explicit — 以“是否促进主动暴露协作问题”作为审核现有设计的主轴。
- 🔍 delegated — 默认从心理安全、问题是否指向协作机制、权力结构和整改闭环四方面审核，不把“认错是否深刻”当作成功标准。
- ❓ ambiguous — 复盘内容是否进入绩效或处分、领导是否也属于被复盘对象、这是一场学习型复盘还是兼有事故问责，尚未明确。

### 需要你拍板的 4 个问题

1. **【测试问责边界；决定复盘与问责是否必须拆开】会上主动披露的失误会怎样影响绩效或处分？**

2. **【测试权力边界；决定领导能否继续主导议程】领导的判断、资源分配和管理方式是否也允许被公开复盘？**

   - B. 可以提，但只允许匿名或会后提交

3. **【测试会议性质；决定是一场会还是两条流程】这次会议本质上是什么？**

4. **【测试成功标准；决定最终审核以什么证据判定有效】未来 1—2 个复盘周期，你最看重哪项可观察变化？**
   - A. 问题被更早提出，且跨角色/机制类问题与整改闭环增加（推荐）
   - B. 每个人承认的个人错误更多、更具体
   - C. 领导确定的整改项按期完成率提高
